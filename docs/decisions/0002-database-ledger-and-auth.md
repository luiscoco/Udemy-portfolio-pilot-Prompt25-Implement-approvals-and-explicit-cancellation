# 0002 — Database identity, ledger and authentication schema

Date: 2026-10-01. Status: accepted for milestone 06.

Choose Better Auth's Prisma-backed database sessions and account identity model for milestone 07's local demo and Microsoft Entra OIDC paths. This migration includes User, Session, Account and Verification with the documented core fields. No auth dependency, login endpoint, session credentials or password is added in this milestone. Milestone 07 must pin the then-current maintained library and check its generated schema before integration. Session token is unique; provider/account identity is unique; expiry and user references are indexed. Do not log auth tables or serialize their contents to the browser. See [Better Auth's core schema](https://better-auth.com/docs/concepts/database).

Security identity is `(exchangeMic, symbol)`, using an uppercase four-character ISO market identifier and uppercase provider-normalized symbol. This identifies a listing, not a company; ACME appears on two exchanges in the fictional fixture to exercise this. USD and STOCK are enforced by SQL CHECK constraints. Symbol normalization and listing validation belong in the future provider adapter.

PortfolioTransaction is the ledger and the only authoritative position input. There is no Position table, persisted balance, or mutable share count. Quantity, unit price and fees use numeric(28,10); total cash amount uses numeric(38,10). Amount is positive cash outflow for BUY (quantity × price + fees) and positive proceeds for SELL (quantity × price - fees), rounded to ten decimal places by PostgreSQL. Negative quantities, zero prices, NaN and inconsistent amounts are rejected. This slice does not expose a trade write API. Chronological weighted-average cost and long-only/oversell validation under transactional locking are milestone 08/09 service responsibilities; row CHECK constraints cannot validate aggregate holdings.

Owner deletion cascades through private portfolios, transactions, watchlists, accounts and sessions. Portfolio deletion removes its ledger. Deleting a referenced security is restricted by transactions/watchlists, protecting history; quotes and news links cascade when an otherwise-unused security is removed. Deleting an article cascades only its links. Updates of referenced identifiers cascade. Market records are shared, while repositories filter them to listings referenced by the authenticated owner's ledger or watchlist.

Repository contexts are opaque objects created only from an unexpired Session lookup. A fabricated `{ userId }` is rejected at runtime. Derive the token from a trusted server cookie and create a new context on every request; do not cache contexts between requests or across logout. Raw Prisma access is infrastructure-only and must not become a browser/model-selected owner bypass. HTTP cookie/origin policy, identity verification and session issuance are milestone 07.

Prisma 7 uses prisma.config.ts for datasource/migration configuration; migrations never trigger this seed. Seeding is an explicit local opt-in, uses fixed fixture IDs and timestamps, executes atomic upserts, and serializes concurrent runs with a PostgreSQL advisory lock. It never creates credentials or usable sessions. The local CLI rejects production and non-loopback connections. See [Prisma 7 configuration and seeding changes](https://www.prisma.io/docs/guides/upgrade-prisma-orm/v7).
